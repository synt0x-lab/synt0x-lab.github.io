What the score means#

CVSS (Common Vulnerability Scoring System) measures the technical severity of a vulnerability, not the risk it poses to you. Version 4.0 says this more plainly than 3.1 did: a score built from the base metrics alone is labelled CVSS-B, and the specification warns against using it on its own to judge risk. The label above the number tells you which metric groups went into it:

  • CVSS-B: base metrics only.
  • CVSS-BT: base and threat metrics.
  • CVSS-BE: base and environmental metrics.
  • CVSS-BTE: all three. This is the one that comes closest to “how urgent is this for us”.

Always quote the label with the number. “9.3” alone doesn’t say whether anyone has looked at your environment or at the threat picture.

What changed from 3.1#

  • Scope is gone. Instead of one Changed/Unchanged switch, 4.0 scores impact twice: on the vulnerable system (the component that contains the flaw) and on subsequent systems (everything beyond it: other services, the host, a victim’s browser). Cross-site scripting (XSS), for example, usually does little to the web application itself but runs in the victim’s browser session, and the vector now says exactly that: no or low vulnerable-system impact, some subsequent-system impact.
  • Attack Requirements (AT) is new. Conditions of the target that the attacker can’t control, such as winning a race or sitting in a man-in-the-middle position, moved here from Attack Complexity. Attack Complexity now only covers security measures the attacker has to defeat, such as ASLR or a secret they can’t simply obtain.
  • User Interaction has two levels: Passive (the victim only has to visit or view something) and Active (they have to do something deliberate, such as open a file or click through a warning).
  • Temporal became Threat, and only Exploit Maturity is left. Remediation Level and Report Confidence were dropped.
  • Supplemental metrics are new: Safety, Automatable, Recovery, Value Density, Response Effort and Provider Urgency. They add context for whoever acts on the finding, and they never change the score.
  • There is no formula any more. See below.

How the score is computed#

3.1 multiplied metric weights. 4.0 sorts every vector into one of 270 MacroVectors: groups of vectors that FIRST considers equally severe, defined by six equivalence sets (for example: is the attack network-reachable, without privileges and without user interaction?). Each MacroVector has a score that a panel of experts ranked. The final score starts from that value and is lowered in proportion to how far the vector sits from the most severe vectors in its MacroVector, scaled by the gap to the next, less severe MacroVector.

The calculator shows the MacroVector as six digits, one per equivalence set; 0 is the most severe level. Two vectors in the same MacroVector can still score differently, because of that distance adjustment.

Where scores usually go wrong#

  • An empty threat group is the worst case. If Exploit Maturity is not defined, it is scored as Attacked. That is deliberate: without threat intelligence, assume the worst. If you know there is no public exploit and no reported attack, set it to Unreported, and the score drops.
  • The same goes for security requirements. Not defined is scored as High. Set them for the asset you are actually assessing.
  • Subsequent system impact is not “this one is serious”. Only score it when the impact reaches a system other than the vulnerable one.
  • Safety is for physical harm. The Safety value of Modified Subsequent Integrity and Availability means people could be injured. It is meant for medical devices, industrial control systems and vehicles, not for “this is important”.
  • Privileges Required is still what the attacker needs before the attack, not what they gain from it.
  • One vulnerability, one score. Score the flaw you found, not the whole attack chain an attacker could build from it.

Privacy and accuracy#

The calculator runs entirely in your browser and makes no network requests. The current vector is kept in the URL fragment (the part after #), so you can bookmark or share a score; browsers never send the fragment to the server.

The scoring is a port of the official FIRST CVSS v4.0 calculator (BSD-2-Clause, © 2023 FIRST.ORG, Inc., Red Hat, and contributors), including its lookup tables and its floating-point arithmetic. That last part matters: the FIRST calculator measures distances in steps of 0.1 as floating-point numbers, so at exact ties it can round differently from an exact computation. Some libraries compute exactly and differ from the official calculator by 0.1 on a few vectors. This one doesn’t: I checked it against scores produced by the official calculator code on all 104,976 base vectors and on 22,000 random vectors with threat, environmental and supplemental metrics, and every score matches.

Vectors must follow the specification strictly: the CVSS:4.0/ prefix, every base metric, and metrics in the order the specification lists them. 3.x vectors are rejected rather than converted, because 4.0 measures different things and there is no correct automatic conversion. For those, use the CVSS 3.1 calculator.
