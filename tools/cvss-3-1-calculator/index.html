What the score means#

CVSS (Common Vulnerability Scoring System) measures the technical severity of a vulnerability, not the risk it poses to you. A 9.8 in a library you never load is less urgent than a 6.5 on your internet-facing login page. Use the base score to describe the vulnerability itself, and the environmental metrics to say what it means for a specific system.

The three metric groups#

  • Base metrics describe the vulnerability itself: how it is reached, what the attacker needs, and what it breaks. They don’t change over time or between environments, and they are what belongs in an advisory or a pentest finding.
  • Temporal metrics describe how the picture changes over time: whether working exploit code exists, whether a fix is available, and how well confirmed the report is. They can only lower the score.
  • Environmental metrics adapt the score to one environment. The requirements say how much confidentiality, integrity and availability matter for the affected asset; the modified metrics account for controls you already have. A service that is only reachable from the same network segment, for example, can set Modified Attack Vector to Adjacent. These can raise or lower the score.

Where scores usually go wrong#

  • Scope is Changed only when the vulnerable component and the impacted component sit under different security authorities: stored XSS (the web application is vulnerable, the victim’s browser is impacted) or a virtual machine escape. It is not a way of saying “this one is serious”.
  • Privileges Required is what the attacker needs before the attack, not what they gain from it.
  • Attack Complexity is about conditions outside the attacker’s control, such as winning a race or needing a man-in-the-middle position. It is not about how hard the exploit was to write.
  • User Interaction is Required when someone other than the attacker has to do something, for example click a link or open a file.
  • One vulnerability, one score. Score the flaw you found, not the whole attack chain an attacker could build from it.

Why 3.1 first#

CVSS 4.0 fixes several of the weaknesses above, but a large share of scanner output, existing advisories and report templates still use 3.1. A 4.0 calculator will follow.

Privacy and accuracy#

The calculator runs entirely in your browser and makes no network requests. The current vector is kept in the URL fragment (the part after #), so you can bookmark or share a score; browsers never send the fragment to the server.

The formulas follow the FIRST CVSS v3.1 specification, including the Roundup function that 3.1 introduced to avoid floating-point rounding errors. Only CVSS:3.1 vectors are accepted: 3.0 vectors use slightly different formulas and would score differently.
